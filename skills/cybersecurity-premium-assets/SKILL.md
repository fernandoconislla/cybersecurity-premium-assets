# Cybersecurity Premium Assets

## Canonical visual style reference — mandatory first load

**For visual style, always read [VISUAL_STYLE.md](VISUAL_STYLE.md) first.** This is the **sole general internal visual reference** for NEW cybersecurity premium assets, distilled from the approved icon family. Use its rules on silhouette, contour weight, white internal spacing, cyan/navy hierarchy, geometric balance, density and 64px readability. **Do not open approved asset SVGs merely to learn the style or copy visual proportions.** A supplied user reference governs the new icon's specific concept, within our hard constraints.

**Separate style lookup from technical validation.** The official `audit_workflow.py` requires **SHA-verified bytes** for all current approved SVGs, but **does NOT require downloading each SVG separately**: use `scripts/approved_masters_pack.json` with `scripts/master_cache.py` to recover exact masters automatically under the audit output when local originals are absent. The cache must cover the complete `approved_masters.json` and every Git blob SHA must match; otherwise the workflow fails closed. Source styling exclusively from `VISUAL_STYLE.md`, never from unpacked masters. For REVISION of an approved asset, retrieve its exact SVG as the editable source.

**Default workflow:** `SKILL.md + VISUAL_STYLE.md` → external semantic references/user-supplied image → original editable SVG → official validator → official auditor (with exact masters used solely for QA) → visual inspection against VISUAL_STYLE.md → approval gate → interactive user choice. Keep the guide general; update it only for a user-approved new family-wide design rule, not after every icon.


## BOOTSTRAP — mandatory environment initialization before every audit

**Root cause addressed:** the GitHub app/connector and the Python filesystem may be isolated. Seeing official files through the GitHub connector does **not** mean they are automatically mounted in the runtime, and Python may not resolve `raw.githubusercontent.com`. Never assume transferred files exist. Do not retry the same inaccessible URL in a loop, substitute unofficial scripts, forge evidence, or skip a gate.

**New official entry point:** `scripts/bootstrap_audit.py` together with a **single** versioned `scripts/audit_runtime_bundle.json`. The bundle contains exact pinned UTF-8 bytes of all six official runtime files: validator, auditor, approval gate, master-cache resolver, pinned index and complete verified master pack. `bootstrap_audit.py` checks bundle Git blobs, pack/index parity, official validator provenance, local file consistency, installed Python dependencies, candidate + previous-version SHA, and the real audit manifest. It stages missing files before attempting any official scripts. **Use `--audit-only` first; inspect the genuine outputs and complete manual evidence; re-run `--audit-only` when the manifest changes; only then run `--gate-only`.** `--execute` is reserved for cases with independently completed and recorded visual evidence. It **never publishes an asset**.

# Inspeccionar 1024/128/64 y hoja familiar; registrar manual_evidence real.

**No working file bridge?** Return `BLOCKED / AUDIT INCOMPLETE` with diagnostic `NETWORK_AND_BUNDLE_UNAVAILABLE` or `BUNDLE_NOT_AVAILABLE`. Do not claim there is a completed audit or show approval controls. The bootstrap supports bounded HTTPS retrieval only when network access works; an offline execution must use a **real local bundle file**. The previous SVG and the manifest are not contained in the bundle and must remain real, separately hashed source inputs. Manual evidence must reflect inspections actually performed.

**Recovery rules:** a mismatched existing official script is an error (`STALE_RUNTIME`); replacement requires explicit `--repair` with a verified GitHub bundle. A corrupt/missing entry, wrong SHA, stale master index or unverified validator always blocks execution. Official masters are reconstructed only for QA in `<output_dir>/verified_masters/`; `VISUAL_STYLE.md` remains the **sole internal style reference**.

**After any approved publication:** update the pinned index, approved-master pack and **audit runtime bundle** (which embeds both). In a full checkout, execute `python scripts/build_master_pack.py --write` and `python scripts/build_audit_runtime_bundle.py --write`, then both `--check` commands and the tests. When updating through the GitHub connector, sync the exact content and hashes for all three artifacts. A stale bundle means next generation is BLOCKED, not permission to skip checks.

**Regression checks:** `python -m unittest discover -s tests -v` includes offline end-to-end gate execution, missing bundle, missing candidate, tampering, hash mismatch and repair. CI success is evidence of repo tests only, **not** proof that the current user candidate has been audited.

## Contract
**Two inputs:** `nombre` (required, non-empty) and `descripcion` (optional). Both values originate **only from the user**. When `nombre` is absent and the user wants to generate an asset, ask for the name; optionally offer a small input screen with required name and optional description. When the user only asks for ideas, propose concepts without treating the proposal as a submitted input. **Never invent or auto-populate `nombre` or `descripcion` and present them as user-supplied.** If `descripcion` is omitted, autonomously choose a sensible visual composition as an internal design decision; keep the input truly absent. A description may change composition, but never override hard rules. Report conflicts.

**Output:** an original, genuine editable SVG `assets/<slug>.svg`, **rendered visibly and directly in the response as an image** (not just described), plus a working download link to the real SVG file. PNG may be a QA preview only, never the substitute deliverable. Verify actual SVG and preview paths exist and the image renders successfully before offering downloads. **A file path printed as text is NOT a visible image; Markdown/image component must display the actual preview.** Only mark as approved after explicit user approval.

## Hard rules
1. Canvas `width="1024" height="1024" viewBox="0 0 1024 1024"`. Background fully transparent.
2. Exactly three global CSS tokens in `<style>`: `--PRIMARY: #092B60;`, `--SECONDARY: #38BDF8;`, `--CONTRAST: #FFFFFF;`. All painted shapes use `.primary`, `.secondary`, or `.contrast` classes reading `var(--TOKEN)`. Values may later change for rebranding; the roles must not change.
3. No fourth colors, gradients, shadows, filters, patterns, opacity effects, raster images, external artwork, or background rectangle. Whites must be internal and enclosed by stronger colored surfaces for visibility on white backgrounds.
4. Main subject's dominant visible dimension ≈ 90% (922 units, tolerance ±2%). Preserve aspect ratio, center *both* axes; keep equal geometric margins on the minor dimension and avoid clipping. Optical offsets of up to 12 units require justification.
5. **Use VISUAL_STYLE.md as the family visual reference, not the approved SVG files.** The approved SVGs remain immutable and are pinned by `scripts/approved_masters.json`; their **exact bytes** are required by the current official auditor for Git blob hash integrity and a QA contact sheet, not to learn or copy design style. For an existing asset revision, retrieve its exact SVG as the input source.
6. Geometry must consist of independently editable paths/shapes, logically grouped and identified. Never modify **any approved reference** as a side effect. Design new assets as fresh files.
7. Verify at 1024, 128 and 64 pixels on white. Evaluate visual coherence first against **VISUAL_STYLE.md**; any family contact sheet from the official auditor is supplemental QA, not the source of styling rules. The icon must read as the named concept without labels.
8. **Color-layout decisions must be justified, never mechanically copied:** All three palette tokens remain globally defined and no fourth color may be used, but splitting an object into cyan/navy halves is **not mandatory**. Decide whether to split based on the concept's geometry, legibility and perceptual benefit. Whenever choosing either **split** or **uniform fill**, state that choice and its specific rationale to the user in the visual audit. If the split is merely decorative, do not use it. A uniform cyan field can retain primary navy outlines and contained white detailing, thereby using the full palette without an arbitrary division.

## Mandatory evidence-based visual-reference research (before drawing)
1. **Search the internet before generating each NEW asset.** Research real, recognizable icons in official design systems and product iconography relevant to technology, IT and cybersecurity; prioritize official sources such as IBM Carbon, Microsoft Fluent, Google Material and Lucide, plus actual cybersecurity/identity product semantics when relevant. Search broadly enough to obtain at least **three genuinely distinct visual precedents**; do not invent reference names, descriptions or images.
2. **Inspect and compare** the found references by concept semantics, technical/cybersecurity fit, immediate recognizability, silhouette orientation, composition, simplicity at 64 px and suitability for our premium family. Show a concise evidence-backed comparison with working source links and explicitly identify the winning reference, its strongest alternatives and why it wins. If research is unavailable, disclose that honestly; do not claim research occurred or fabricate citations.
3. **Semantic precision:** a user/avatar is not automatically an authenticated user; a shield, key, badge, lock or network detail changes the concept. Differentiate router vs Wi-Fi, organization vs org chart, malware vs generic software bug. Use technical standards for semantics and premium references for geometric refinement as separate evidence. Avoid extra motifs unless the supplied `nombre` or `descripcion` warrants them. Use industry-standard metaphors rather than imaginary novelty.
4. **Original vector reconstruction:** inspect and reinterpret the reference's *concept, orientation, silhouette, curve quality, proportions, detail hierarchy and repeated-element count*, without copying protected path data. User-provided imagery takes precedence and may guide a close formal reinterpretation through original vector paths. Build independent, editable geometry, respect source licensing and the immutability of our existing approved assets. User-provided image references take precedence for intended silhouette unless the user explicitly asks for a new researched direction.
5. **Iterate before the approval gate:** compare the candidate with the user-provided or winning semantic reference, the preceding version, and **VISUAL_STYLE.md** (never use every approved master as a shape template). Track accepted and rejected geometry; fix critical visible defects prior to seeking approval. If incremental edits do not improve the design, rebuild fresh original SVG geometry instead of patching. Fix visible design defects, run the SVG validator and inspect at 1024/128/64. Never invent tests, scores, downloaded paths or visual assessments. Explain the design decisions (including split vs uniform fill) and remaining limitations.

## Mandatory optimization state machine — persistent revision
An optimization of an **unapproved** SVG inherits its name, prior candidate bytes and SHA-256, user constraints, previous feedback and approved family. It is NOT a new input request, raster image task or approval. The only permitted result is a new independently editable SVG version with genuine renders, comparison, audits and interactive approval.

**Mandatory transitions:** `REVISION_REQUEST -> LOAD_SOURCE -> CAPTURE_DECISIONS -> BUILD_SVG -> VERIFY_FILE_AND_HASH -> VALIDATE_OFFICIAL -> AUDIT_WORKFLOW -> INSPECT_VISUALS -> DELIVER_INLINE -> APPROVAL_FORM -> WAIT_FOR_USER`. On failure, repair at the failed stage; never skip or reinterpret earlier user decisions.

- **LOAD_SOURCE:** fetch current `SKILL.md` and `VISUAL_STYLE.md`; retrieve the candidate V(n-1) exact SVG and SHA. Stage `bootstrap_audit.py` plus the **single** verified `audit_runtime_bundle.json` into the runtime; use the bootstrap to prepare all other official files. Never treat connector responses as filesystem bytes. Missing prior revision source is a hard blocker.
- **CAPTURE_DECISIONS:** internally list PRESERVE, CHANGE, REJECT and VERIFY. Revision instructions do not become an invented original `descripcion`. "No other protagonists" forbids adding a separate lock, screen, document, shield or badge.
- **BUILD_SVG:** write V(n) as an actual editable text SVG using only the three CSS classes. **Never use image generation as a substitute** for the SVG or its deterministic renders; an image-only artifact is not a candidate.
- **VERIFY/VALIDATE/AUDIT:** save real bytes, calculate SHA-256, and run both `validate_asset.py` and `audit_workflow.py`. Set manifest `mode: "revision"`, `previous_candidate` and `previous_sha256` to the exact V(n-1) file and hash; the auditor fails closed if any prior file is absent or altered. Fix any failure before advancing.
- **INSPECT/DELIVER:** inspect actual renders at 1024/128/64, V(n-1) vs V(n), the internally generated family QA sheet, the eight hard-rule results and ten visual findings. Show real inline images, exact SVG download, two separate audits and the stateful approval form. Never finish with only generated imagery, plain paths or a static fake form.
- **WAIT:** no GitHub publication before explicit user approval; a rejected candidate remains unapproved. On approval publish exact bytes, verify blob and unchanged masters, then append its Git blob SHA to `scripts/approved_masters.json`, also update `scripts/approved_masters_pack.json` with the exact approved SVG bytes, and register it in the skill/catalog. Verify index/pack parity before completing publication.

The executable auditor is the required **preflight authority for reproducible evidence**; artistic quality, source credibility and ChatGPT interaction must still be inspected manually. It cannot confer publication authorization.

## Mandatory visual-design audit
Evaluate each category separately with an evidence-based 0–10 score and a concrete finding:
1. **Concept recognition:** verify meaning even at 64px, distinguish the technical concept from generic icons, and identify alternative readings or unwanted semantics created by extra motifs.
2. **Premium refinement:** audit Bézier tangencies, contour continuity, curve smoothness, optical alignment, corners, extremity endings, white-border thickness and intentional negative space; do not award high scores automatically.
3. **Composition and hierarchy:** coherent focal point, intentional negative space, no competing decorations.
4. **Geometry and volume:** verify plausible connections, overlaps, separation lines reaching their intended edges, no floating components or accidental containers. Check the precise count, orientation, direction and spacing of repeated elements; if symmetry is required, confirm geometric mirroring, not just approximate appearance. For stacked forms, separations must visibly join lateral edges.
5. **Optical balance:** perceived mass and left/right distribution, beyond mathematical centering.
6. **Visual-family consistency:** assess contour hierarchy, enclosed white dividers, relative color dominance, curve quality, density and optical scale against **VISUAL_STYLE.md**. Use the auditor's all-master contact sheet only as a secondary QA cross-check, not for deriving the style. Match the graphic language, not either icon's silhouette.
7. **Color-role composition and explicit decision:** only approved tokens, contrast on white, and independently assess relative cyan/navy/white visible area, cyan surface prominence when meaningful, and white-border weight against **VISUAL_STYLE.md** and, if generated, the auditor's secondary QA contact sheet; reject excessive visual dominance unless semantically justified. Cyan is often the main surface but not a mandatory percentage.
